# =============================================================================
# Documentation System manifest
# =============================================================================
# Classifies every file in the template so the installer knows what to copy
# and what an update may replace. One entry per line: <kind> <path>
# A path ending in "/" covers every file under it. Each tracked file must
# match exactly one entry - .docsys/bin/check-manifest.sh enforces this.
#
# Kinds:
#   owned         System file. Installed, and replaced on every update.
#   seed          Project starter. Installed only if missing, never updated.
#   block         Project file with a managed block between
#                 "<!-- docsys:begin" and "<!-- docsys:end -->". Installed if
#                 missing; on update only the block is replaced.
#   guide:<name>  Optional guide, picked at install by name. A guide's starter
#                 files share its name and install with it - a foundation
#                 guide's sit in its implementation pack under
#                 .claude/skills/apply-guide/<name>/. Updated only if installed.
#   addon:<name>  Optional add-on, installed on request as a group. Its files
#                 live in addons/<name>/, laid out as they land in the
#                 project: addons/<name>/x/y installs as x/y.
#   repo          Template repo only. Never installed.
#
# Mirrors (three fields): mirror <from-prefix> <to-prefix>
#   Installs every owned file whose path starts with <from-prefix> a second
#   time, with that prefix swapped for <to-prefix>. Used to give Cursor its
#   own copy of the commands.
#
# Stacks (three fields): stack <name> <guide,guide,...>
#   A named set of guides for one technology stack. `--stacks <name>`
#   installs them all, and a later update adds any guide the stack gains.
#   Every name must be a guide in this manifest.
# =============================================================================
